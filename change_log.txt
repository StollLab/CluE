--------------------------------------------------------------------------------
CluE Oxide: 1.0.0-dev

NOTE:
  This version changes the layout of the input file (see the CHANGED
  entries "The input file has a new layout" and "In [[groups]], the table
  selection is replaced"). The entries of this version that were written
  before that change name input keys by their old names, such as
  cluster_method, ensemble_cce, selection.within_distance, and cell_type;
  those two entries give the new name of each key. Some of the old keys,
  such as cell_ids and primary_cell, were removed (see REMOVED).

ADDED:
  Output directories can be resumed. Each output directory has a record,
  clue_manifest.toml, with the CluE version, the version of the Rust 
  compiler that built CluE, the main seed, run.cluster_batch_size, a 
  fingerprint of the settings that affect the computed signals, the 
  hashes of the files read during the run (cluster files and 
  partition-table csv files), and the progress of every structure, 
  instance, and orientation. A run into an existing output directory
  * loads the saved signal and prints "Output in <dir> is already 
    complete; no calculations are needed." if everything is computed and
    every requested file is present;
  * otherwise resumes it: complete instances and orientations are loaded,
    saved auxiliary-signal batches are reused, and the rest is computed.
    Instances or orientations whose requested files are missing (for 
    example methyl_partitions = true after a run without it) are computed
    again, with the same result;
  * stops with an error if the directory holds the output of a different
    simulation: another CluE version, other settings or input-file 
    contents (the differing settings are listed; if the output was 
    written by a build with another Rust compiler, the message says that
    the differences may be formatting only), another or a missing 
    run.rng_seed (the message gives the recorded seed), a structure that 
    is no longer an input or whose file contents changed, fewer 
    run.number_runs than recorded, or a different run.cluster_batch_size
    while the output is incomplete. A directory that is not empty but has
    no clue_manifest.toml (for example the output of an earlier version)
    is also an error.
  run.number_runs can be increased to add instances to an output; the 
  first instances are the same as before. Changing output switches does 
  not start a new simulation.

  The main seed is always written to <output>/rng_seed.txt and printed. 
  Without run.rng_seed, it is drawn from the operating system's entropy
  (at most 2^63 - 1, so that it can be given as rng_seed in the input).

  clue_oxide -c (--check) now also checks the existing output directory
  after the input file, without writing anything, and prints one line for
  each, for example
    in.toml: input OK
    in.toml: output out: complete; a run will do no calculations
  The output line says whether a run would start a new simulation, find a
  complete output, resume (with the number of complete instances and 
  orientations), or stop, with the error the run would give. If the input
  has errors, the output is not checked. The exit code is 0 only if both
  are fine. Previously the only output line was "<file>: OK".
  Library: clue_oxide::check() and CheckReport.

  Library: output_manifest::inspect_output() reports what a run would do
  with its output directory, io::structure_output_dirs() lists the 
  structures of an output directory with their directories, 
  Config::physics_fingerprint(), Config::structure_inputs(),
  Structure::build_structure_from_file(), io::write_atomically(), and
  math::fnv1a_64() (64-bit FNV-1a hash).

  A build script (build.rs) records the version of the Rust compiler 
  (CLUE_RUSTC_VERSION) for clue_manifest.toml.

  The key kmeans_iter_cap (default 1000, must be at least 1) sets the
  maximum number of k-means iterations for partitioning = "kmeans" and
  "restricted_kmeans". If k-means has not converged by then, a warning is
  printed and the last assignment, which is a valid partition, is used.

  The key detected_spin.weight_tolerance (default 1e-9) sets how far the 
  sum of the weights of a detected spin probability grid may differ from 
  one.

  CluEError implements std::error::Error, so library users can return it
  as Box<dyn Error> or pass it to other error-handling code.

  The group key abundance_tolerance (default 1e-9) sets how far the sum 
  of a group's isotope abundances may differ from one.

  The key orientations.weight_tolerance (default 1e-9) sets how far the 
  sum of the weights of an orientation grid given by a file or by 
  vector_grid may differ from one. Weights that differ by more are an 
  error; weights within the tolerance are normalized. Previously the 
  weights were used as given, and the signal was scaled by their sum.

  The command line option -c, --check reads and checks an input file
  without running it: it reports unknown or misplaced keys, missing
  settings, and missing files, prints "<file>: OK" or the errors, and
  exits with 0 or 1. Errors that depend on the structure (group names,
  overlapping groups, empty selections) are still found only by a run.

CHANGED:
  New layout of output directories. Each instance of run.number_runs has
  its own directory (fixes N04 of report.md: with number_runs > 1, all
  instances shared one directory, so with auxiliary_signals = true every
  instance reloaded the checkpoints of the first, and the average equalled
  the first instance):
    <output>/clue_manifest.toml, rng_seed.txt, tau_axis.csv, signal.csv
    <output>/structures.csv   (id, file, content_hash, weight, 
                               number_runs, directory)
    <output>/structures/<id>/signal.csv   (average over the instances)
    <output>/structures/<id>/instance_<k>/signal.csv, info/, 
      orientations/theta_<θ>deg_phi_<φ>deg/
  <id> is s_<16 hex digits of the FNV-1a hash of the structure file
  contents>. Previously instances were written to <output>/<run_name> or
  <output>/run-<hash of the structure>. A cluster_expansion.clustering.file
  directory taken from an earlier run is now 
  <output>/structures/<id>/instance_<k>/orientations.

  Seeds. Each structure has a seed derived from the main seed and the hash
  of its file contents, each instance a seed drawn from the structure 
  seed, and each orientation a seed drawn from the instance generator 
  after the structure, the coupling tensors, and the orientation grid are
  built. The bath populations, mean fields, and k-means partitions of an 
  orientation use its own seed, so orientations do not depend on the order
  in which they are computed. Results with a given rng_seed therefore 
  differ from earlier versions (statistically equivalent); results that do
  not depend on the seed, such as the 1omp test, are unchanged.

  The default output directory (no output.directory) is now 
  CluE-<16 hex digits>, the FNV-1a hash of the settings and the main seed.
  It no longer depends on the Rust release (math::str_hash used
  DefaultHasher; O07 of report.md), on output switches, on 
  run.number_runs, or on the structure file name. Without run.rng_seed, 
  each run therefore gets a new default directory.

  Signal, batch, tau-axis, and record files are written to <file>.tmp and
  then renamed, so an interrupted run never leaves a partly written file.
  A saved auxiliary-signal batch file that does not match its batch (wrong
  number of signals or time points, or unreadable) is computed again and
  overwritten, with a message, instead of stopping the run.

  The group isotope tables (ParticleProperties::isotope_properties) are
  kept in a BTreeMap instead of a HashMap, so that the settings 
  fingerprint does not depend on the order of a hash map.

  Library: signal::calculate_signal::calculate_signals() takes the config
  and an output_manifest::OutputState instead of a random number generator
  and a save path. Structure::build_structure() is unchanged.

  The integration tests write to temporary directories instead of 
  CluE-<hash> directories in the working directory.

  Molecules are now always the complete sets of bonded atoms (from the
  CONECT records). Previously an atom bonded to two atoms that were each
  not bonded to any earlier atom in the file left the molecule split into
  fragments; for example, the R1 spin label of the 1omp test structure was
  split from the protein. This affects cosubstitute = "same_molecule",
  same-molecule particle selections (same_molecule, from_same_molecule_as,
  to_same_molecule_as), and making molecules whole across periodic 
  boundaries. With cosubstitute = "same_molecule", the particles of a
  group in one molecule now always share one isotope draw; other groups in
  the same molecule keep their own settings. Results can change for
  structures whose atom order split molecules.

  K-means partitioning first splits the bath into groups of coupled spins.
  This step now takes time and memory proportional to the number of spins
  and couplings; previously it needed memory proportional to the number of
  groups times the number of spins (about 1.5 GB for 8000 uncoupled spins,
  and about 9.6 GB for 20000). The groups, and so the partitions, are 
  unchanged.

  K-means partitioning ("kmeans" and "restricted_kmeans") now keeps the
  blocks given in partition_table and clusters only the remaining spins.
  Previously it overwrote them, and every run that combined k-means with a
  partition_table stopped with an incomplete-partition error.

  partitioning = "restricted_kmeans" now groups spins by position. The cost
  of assigning a spin to a cluster was the distance in metres rounded to an
  integer, which is 0 for every pair, so the clusters were spatially 
  arbitrary. The cost is now the squared distance, scaled by the largest
  squared distance to integers up to 10^6, which does not depend on the
  unit of length and matches the k-means center update. Restricted k-means
  results therefore differ from earlier versions.

  partitioning = "kmeans" and "restricted_kmeans" no longer hang. The
  search for connected groups of bath spins never marked a spin as
  visited and so never finished. K-means partitioning also now uses the
  coordinates of the active bath spins being partitioned; previously it
  used the active-spin index as a bath-particle index, which picked
  unrelated particles (or panicked when every bath particle was active).

  K-means partitioning ("kmeans" and "restricted_kmeans") no longer fails
  with an incomplete-partition error, and no longer silently merges blocks 
  from different groups of coupled spins, when a k-means cluster is left
  empty: block IDs are now renumbered without gaps. The initial k-means
  centers are now k distinct spin positions chosen at random (Forgy
  initialization) instead of random points in the bounding box, so
  unrestricted k-means no longer leaves clusters empty for distinct
  positions. K-means results for a given rng_seed therefore differ from
  earlier versions. A group of coupled spins with fewer than about 
  kmeans_size/2 spins now becomes one block instead of causing a panic.

  The column headers of the top-level signal.csv are now signal_0 ...
  signal_N (N = max_cluster_size), the same as the per-instance and
  per-orientation signal.csv files. Previously they were signal_1 ...
  signal_{N+1}, so the column named signal_k held the (k-1)-th order
  result. Only the labels change; the data and column order are the same.

  The test reference signal assets/1omp_K26R1_0.003228966616048703_signal.csv
  was regenerated after the update of the physical constants to CODATA
  2022. The new constants change the 1omp signal by an RMSD of 7.7e-9;
  with the previous constants, the current code reproduces the old
  reference to an RMSD of 7.5e-14. Unit tests in quantum/tensors.rs that
  hard-coded CODATA 2018 values (γe, γp, μN/h) now use the CODATA 2022
  values from NIST.

  gCCE signals for the fid, hahn, CP-n, free-evolution and custom pulse
  sequences are now Tr[ρ D(t)]. Previously they were Tr[ρ^T D(t)], which
  is the same only when the density matrix ρ is real and symmetric.
  Results change when ρ is complex: with
  thermalize_cluster_populations = true, with populations = "random",
  with populations = "thermal" and ensemble_cce = false, or with a complex
  detected_spin.density_matrix (for example "Sy" or "S+"). The refocused
  Hahn echo and CCE were already correct.

  Every element of a selection list must have the type of that list:
  integer lists (serials, residue_sequence_numbers, indices, cell_ids, and
  their bonded_ and not_ forms) take non-negative integers, and the other
  lists take strings. Any other element is now an error that names the
  key and the position, for example
  selection.serials[1] must be a non-negative integer, but got "13".
  Previously such elements were ignored, negative integers wrapped around
  to large numbers, and integers above 4294967295 in u32 lists were
  truncated. A list with no valid elements, such as serials = ["12"],
  was therefore empty and selected every particle.

  A selection with not_cell_ids, or with primary_cell = false, and no
  cell_ids now selects the particles outside the listed cells. Previously
  such a selection matched no particles, so the group's settings were
  silently not applied.

  Structure::new() now puts all particles in the primary cell (cell IDs,
  primary cell indices, and cell indices are set). Previously these were
  empty until the structure was built, so using a particle filter on such
  a structure (library API) could panic. Runs from a config file are
  unchanged.

  Write failures in the tensors, bath, exchange-group, partition-table,
  cluster, and structure PDB output files are now reported as
  cannot write to "<file>": <reason>. Previously the tensors, bath, exchange-group,
  partition-table, and cluster files were not flushed explicitly, so an
  error such as a full disk could leave the file truncated or empty while
  the run reported success; partial writes were also not detected. Files
  written without errors are unchanged.

  Integer arrays in the config are range checked instead of being
  converted with a silent wrap-around:
  - replicate_unit_cell must have exactly three integers from 0 to
    2147483647. Previously fewer than three crashed the program, entries
    after the third were ignored, negative values or values above
    2147483647 crashed when the cells were built, and 4294967296 was
    read as 0.
  - Serial numbers in detected_spin.position must be from 0 to
    4294967295; previously -5 was read as serial 4294967291.
  - partition_table (inline or csv): negative entries, block 0 (reserved
    for the detected spin), serial numbers above 4294967295 (previously
    reduced modulo 2^32, so 4294967306 was read as serial 10), and serial
    numbers not in the structure are errors that name the entry.
    Previously these crashed the program or used a different particle.
    Entries for inactive particles are skipped, as they have no
    partition block; previously they crashed the program.
  - The error for partition blocks with gaps now says that the block
    numbers in partition_table must be 1, 2, ..., k.

  Error messages were corrected and made more specific; which inputs are
  accepted is unchanged. In particular:
  - Invalid config values name the key, and the group and isotope where
    they apply, for example
    group "methyl": drop_probability must be a float, but got string.
    Missing keys say what requires them, for example
    orientations.number is required for orientations.grid = "lebedev".
  - Unknown config keys are reported as invalid key "foo" (previously as
    a TOML file named "invalid key foo").
  - Parse errors list the valid options (cluster_method, pulse_sequence,
    partitioning, orientations.grid, detected_spin.frame, cell_type,
    spin operators, and units).
  - File errors give the reason from the operating system and distinguish
    opening, reading, and creating files; PDB lines that cannot be parsed
    give the file name and line number. This includes errors writing
    output files, creating output directories (for example
    cannot create directory "out/info": Not a directory (os error 20)),
    and writing the cluster and auxiliary signal batch files, which are
    reported as CSV write errors. Grid files with rows of different
    lengths give the csv error, which names the line.
  - Errors in pulse_sequence steps give the step index.
  - Clash and NaN-tensor errors give the PDB serial number and unit cell
    of the particles; diagonalization errors give the matrix size and the
    number of NaN or infinite entries instead of the whole matrix.
  - Messages that named old keys (do_replicate_unit_cell,
    detected_spin_identity, detected_transition, orientation_grid) now
    use the current keys, and spelling and spacing errors were fixed.
  - thermalize_cluster_populations = true without ensemble_cce = true and
    a Stevens coefficient entry with more than one column have their own
    error variants (ThermalizationRequiresEnsembleCCE,
    InvalidStevensCoefficientShape) instead of CluEError::Generic; the
    Stevens error gives the entry index and its shape.
  - TOML sub-tables that cannot be parsed are reported as
    cannot parse TOML: <reason>; previously the reason was quoted as if it
    were the input.
  - Error variants for the detected spin use one name: NoCentralSpinCoor
    is now NoDetectedSpinPosition, NoCentralSpinIdentity and
    NoCentralSpinTransition are now NoDetectedSpinIdentity and
    NoDetectedSpinTransition, and NoCentralSpin and NoDetectedSpinNotSet
    are now NoDetectedParticle. CluEError::Error, used only by pyclue, is
    now CluEError::Python.
  - Misspelled error variants were renamed:
    LenghMismatchTimepointsIncrements to LengthMismatchTimepointsIncrements,
    InorrectNumberOfCellOffsets to IncorrectNumberOfCellOffsets, and
    PartitionIsIncomplette to PartitionIsIncomplete.
  - Failures to write the signal and data CSV files give the reason from
    the operating system, for example
    cannot write CSV file "out/signal.csv": <reason>, with the new variant
    CluEError::CannotWriteCSV. Previously Signal::write_to_csv and
    write_vec_signals dropped the reason, and write_data printed it inside
    the quoted file name.

  PDB files with more than 99999 atoms in the selected model, or more than
  9999 residues in a chain, are now an error, since the PDB format cannot
  number them uniquely. Previously such files stopped with an error about a
  duplicate serial or a line that could not be read. A residue sequence
  number that is not a decimal integer or blank (for example the hybrid-36
  number A000) is now an error; previously it was read as missing.

  Grid csv files (detected_spin.position = "file.csv" and orientation grid
  files) no longer need a header line. The first line is skipped only if 
  none of its entries is a number; previously it was always skipped, so 
  a file without a header silently lost its first point. Spaces around 
  entries are ignored, and an entry that is not a number is an error that
  names the line.

  The orientation grid written to info/orientation_grid.xyzw now holds the
  right coordinates for every point. Previously only the first row was 
  right; the weights, orientation_grid_polar.csv, and the signals were not
  affected.

  For PDB files without element columns (77-78), the rules that read the
  element from the atom name now also use the rest of the model: a name
  starting with H is hydrogen ("HG", "HE", "HO" in amino acids were read
  as Hg, He, Ho, so protons disappeared from the bath or became 165Ho);
  two letters that form an element are read as that element for the only
  atom of a residue (ions such as CA, CL, HG); if no name in the model is
  right-justified as the PDB format requires, names are read as
  left-justified (an amino acid "CA" is carbon, not calcium); otherwise a
  name such as "CL1" is chlorine (was carbon). Outside single-atom
  residues, two letters are read only as elements up to uranium. Instead
  of a count, CluE Oxide now prints the number of atoms per element and
  lists the names that could also denote another element, or that were
  read as D or T. Files with element columns are not affected.

  Structure.write_gro (pyCluE) now writes a valid GRO file of the primary
  cell: the detected spin as atom 0 of residue DET, then every primary
  cell particle, then the unit cell box in nm (zero if there is no unit
  cell). Coordinates have three decimal places, and velocities are no
  longer written. Previously the atom count included the periodic copies,
  the box line was missing after replication or garbled (meters, no
  spaces, one wrong entry), and a Structure made with the constructor
  was written without atoms. A unit cell that GRO cannot represent (first
  edge not along x, or second edge not in the xy plane) is an error.

  Group distance selections (selection.within_distance and
  selection.not_within_distance) are now measured from the detected spin.
  Previously they were measured from the origin of the structure file.

  Groups outside the primary cell are now assigned per unit cell, so
  distance and cell ID selections are evaluated for each periodic copy.
  Cosubstitution groups outside the primary cell are built from these
  per-cell groups, and spin properties of periodic copies come from the
  group of the copy rather than the group of the primary cell particle.

  A group used to place the detected spin (a centroid over groups) can no 
  longer use a distance selection, and such configs now report an error.

  Tensor axes that refer to groups (from/to, from_bonded_to/to_bonded_to, 
  from_same_molecule_as/to_same_molecule_as) are now resolved within the 
  unit cell of the particle, so periodic copies get the same axes as the 
  primary cell particle. Previously bonded and same-molecule references 
  crashed for periodic copies, and group references could match particles 
  in other unit cells. The selections bonded_indices and not_bonded_indices 
  now also apply to periodic copies.

  Structures are now reproducible for a fixed rng_seed when several 
  drop_probability values are used. Previously the order of the random 
  draws could change from run to run. The random draws for such configs 
  differ from earlier versions.

  Groups with cell_type = "primary_cell" or "extracells" now decide 
  whether a particle can carry a spin from the group that applies in its 
  own unit cell. Previously the result depended on the order of the 
  groups, and an "extracells" group could be ignored entirely.

  Cosubstitution groups (for example cosubstitute = "same_molecule") are 
  now copied to other unit cells and dropped with drop_probability 
  whenever any of their particles can have a spin. Previously only the 
  first particle of the group was checked, so a molecule whose first atom 
  has no spin (for example the oxygen of a water) was never copied and 
  never dropped. In the primary cell, whether a group can be dropped is 
  now decided from the groups rather than from the sampled isotopes. 
  Particles without spin are still not copied to other unit cells.

  Molecules that are split across the unit cell boundary are now made 
  whole using the bonds in the structure file before the unit cell is 
  replicated, which also works for oblique cells. Previously this step 
  never ran, so methyl rotors, same_molecule groups, and bond-based 
  selections could combine atoms from different periodic copies. 
  Structures whose molecules are already whole are unchanged. A message 
  reports bonds that are still longer than 3 angstroms afterwards, such as 
  those of structures bonded to their own periodic copies.

  With replicate_unit_cell = true, the number of unit cells is now the 
  number needed to include every periodic image within the radius, which 
  accounts for oblique unit cells and for atoms outside the unit cell. It 
  is never less than in earlier versions, so results for rectangular cells 
  with the atoms inside the cell are unchanged. If the number of unit 
  cells is given explicitly and is too small, a message is printed.

  Replicating a unit cell whose space group is not P 1 is now an error, 
  since only lattice translations are applied. The placeholder 1x1x1 A 
  unit cell that PDB files use for structures without a unit cell, and 
  unit cells without volume, are now ignored. A structure that spans more 
  than two unit cells along a cell edge is now an error when the unit cell
  is replicated, since the unit cell cannot describe it; with 
  replicate_unit_cell = false, a warning is printed and the atoms are left
  where the structure file puts them.

  Building the structure is faster and uses less memory for large 
  periodic systems, with identical results: the clash checks 
  (clash_distance and clash_distance_pbc) only compare nearby particles, 
  unit cells with the same groups share them, and the unit cell of each 
  particle is stored instead of searched for.

  Periodic copies that cannot be within the radius are no longer stored,
  which reduces the memory used for large periodic systems (from about
  1.06 GB to about 0.15 GB for a 7 nm box with 125 unit cells) and makes
  building the structure faster. Exchange groups, such as methyls, are
  kept or skipped as a whole. The spin system and the signals are
  unchanged, but periodic copies have different indices: the bath output
  file lists fewer particles, and cluster files and partition tables
  written by earlier versions for replicated structures do not match
  structures built by this version.

  PDB element symbols in upper case, as the PDB format writes them (for 
  example FE, NA, CL), are now read. Previously atoms with two-letter 
  elements in upper case were skipped. If the element columns are missing 
  or blank, the element is now read from the atom name, with a message; 
  previously this was an error. Lines that are too short or contain 
  non-ASCII characters in fixed columns are now reported as errors 
  instead of crashing CluE Oxide.

  Isotopes drawn for a fixed rng_seed can differ from earlier versions for 
  configs with isotope abundances, since particles that are not 
  cosubstituted no longer reserve an extra, empty cosubstitution group. 
  The isotope statistics are unchanged.

  Selections of serials, names, residues, chain IDs, and residue sequence 
  numbers no longer select particles without that field, such as atoms 
  whose residue sequence number is not a number. Previously such particles
  passed every one of these selections. A message reports how many 
  particles of each group lack a selected field. "not_" selections are 
  unchanged.

  The detected spin position now reports an error if a group or serial 
  number used to place it matches no atom, or if the position is not 
  finite. Previously an empty selection gave NaN coordinates without an 
  error, and an empty group or missing serial among several was ignored.

  Isotope abundances of a group, when given, must now list every isotope 
  and sum to one within abundance_tolerance; they are then normalized, with
  a message if this changes them by more than rounding. Negative 
  abundances are errors. Previously abundances that summed to less than 
  one left the remaining particles with the structure file isotope, and 
  abundances that summed to more than one depended on the order of the 
  isotopes. Existing configs that list only a minor isotope, such as 
  2H.abundance = 0.3 alone, now fail to load and must list every isotope.

  drop_probability must now lie in the interval [0, 1]; other values are 
  errors.

  The element symbols D and T, in structure files and in element 
  selections, are still read as hydrogen, but a message now reports this.

  For a detected spin given as a probability grid, the bath is now 
  centered on the weighted mean of the grid instead of the unweighted mean 
  of its points; the system radius, distance selections, the number of unit
  cells, and the detected spin in the output PDB file use this center.
  Hyperfine couplings are unchanged.

  The weights of a detected spin probability grid must now sum to one 
  within detected_spin.weight_tolerance; they are then normalized, with a 
  message if this changes them by more than rounding. Previously the 
  weights were used as given, so weights that did not sum to one scaled the
  point-dipole hyperfine couplings.

  A detected spin position given as coordinates, [x, y, z], is now read 
  in unit_of_distance, as grid positions and all other distances are. 
  Previously it was always read in angstroms. A position given as three 
  integers, which is read as serial numbers, now prints a message.

  pyCluE load_auxiliary_signals loaded each auxiliary_signals file into
  the clusters one size below it (cluster_size_1 into the empty cluster,
  and so on), which panicked for any real run. Files are now loaded into
  the cluster size they were written for.

  The auxiliary signal of the empty cluster (the bare detected-spin signal
  in gCCE, all ones in CCE) is now saved as
  auxiliary_signals/cluster_size_0_batch_0.csv, so that the saved
  auxiliary signals contain every factor of the signal. Results are
  unchanged.

  Loading saved auxiliary signals, by a run or by pyCluE, now stops with an
  error if a file does not have one signal per cluster of its batch, or if
  its signals do not have the number of time points of the run.
  Previously the signals were attached by position without checks, which
  could attach wrong signals or panic. cluster_batch_size = 0 is now an
  error; previously the run never finished.

  Input keys are now checked per table. Previously a key was accepted if
  its name was allowed anywhere in the input, so a key in the wrong table
  (for example radius under [detected_spin]) or an option value used as a
  key (lebedev = 1) was ignored without an error. Every key that is not
  allowed in its table is now reported, all together, with its full path
  (for example groups[2].selection.not_elemnts, counting [[groups]]
  entries from 0) and, for a known key, the table it belongs in. Input
  files that worked only because such a key was ignored now stop with an
  error.

  A run now first checks that the settings it needs are set (for example
  input_structure_file, radius, magnetic_field, detected_spin.position,
  pulse_sequence, number_timepoints, tau_increments, cluster_method,
  max_cluster_size), that settings required by other settings are set
  (temperature for populations = "thermal"; for cluster_method = "gcce",
  detected_spin.detection_operator, detected_spin.density_matrix, and the
  temperature they or thermalize_cluster_populations need), that settings
  do not conflict (mean_fields = true with ensemble_cce = true), and that
  the structure file, the cluster file or directory, and a csv
  partition_table exist. All problems are reported together before any
  work is done. Previously each was found on its own, partway through the
  run. This also applies to pyCluE's PyConfig.run.

  The detected spin is checked before a run. detected_spin.multiplicity
  must be at least 2 (a spin-0 detected_spin.identity gives 1); 
  previously gCCE then panicked. For CCE and gCCE, detected_spin.transition
  is required when the multiplicity is not 2, and must name two different
  levels from 0 to multiplicity - 1; previously a missing transition 
  stopped the run after the clusters were built, a level out of range 
  panicked, and two equal levels gave a misleading error (CCE) or 
  meaningless signals with no error (gCCE). For gCCE, the levels of a
  detection_operator = [i, j] must also be in range.

  The input file has a new layout; input files must be converted. The top
  level now holds only tables, and every former top-level key moved into
  the table of what it controls:
    [units]: distance, energy, magnetic_field, time (were unit_of_*).
    [structure]: file (was input_structure_file), pdb_model_index, radius,
      replicate_unit_cell, clash_distance, clash_distance_pbc.
    [detected_spin]: gains max_spherical_tensor_rank, which also limits
      the zero-field terms of the bath spins.
    [conditions]: magnetic_field, temperature.
    [pulse_sequence]: sequence (was pulse_sequence), number_timepoints,
      tau_increments, number_timepoints2, tau2_increments.
    [cluster_expansion]: method (was cluster_method), max_cluster_size,
      ensemble (was ensemble_cce), populations, mean_fields,
      thermalize_cluster_populations.
    [cluster_expansion.clustering]: file (was cluster_source), max_spins,
      partitioning, kmeans_size, kmeans_iter_cap, partition_table,
      connect_exchange_groups.
    [cluster_expansion.clustering.pair_cutoffs]: was [pair_cutoffs].
    [run]: rng_seed, number_runs, parallel (was run_in_parallel),
      cluster_batch_size.
    [output]: gains directory (was output_directory) and run_name.
  Values, types, defaults, and units are unchanged. A key of the old
  layout is rejected with what replaced it, for example
  "radius: moved to structure.radius". Error messages name keys by their
  new path.

  In [[groups]], the table selection is replaced by the tables include and
  exclude and the group key cells:
    selection.X               -> include.X
    selection.not_X           -> exclude.X
    selection.bonded_X        -> include.bonded_to.X
    selection.not_bonded_X    -> exclude.bonded_to.X
  for the attributes elements, serials, names, residues, chain_ids,
  indices, and residue_numbers (was residue_sequence_numbers);
  selection.within_distance = b and selection.not_within_distance = a
  become include.distance = [a, b], with [0.0, b] and [a, inf] for one
  bound (integers are accepted); selection.cell_type = "all_cells",
  "primary_cell", "extracells" and selection.primary_cell = true / false
  become cells = "all", "primary", "extra" / cells = "primary", "extra".
  A selection table that held only cell_type or primary_cell selected
  every atom of its cells; its new form also needs include = {}, and the
  hint for these keys says so. Otherwise the same atoms are selected as
  before. A list can now also be given as a single value without brackets
  (elements = "H"). Each old selection key is rejected with its new key.
  The keys combine as the old keys did. An atom must meet every key of
  include. Each key of exclude excludes on its own:
  exclude = {elements = "N", residues = "PRO"} excludes all nitrogen
  atoms and all atoms of PRO residues, not only the nitrogen atoms of
  PRO. Each key of bonded_to is a separate condition that can be met by a
  different bonded atom: include.bonded_to = {elements = "C",
  residues = "SOL"} requires a bonded carbon and a bonded atom of SOL,
  not one bonded carbon of SOL.

  A group with neither include nor exclude is now an error that names the
  group. Such a group selected no atoms, so its settings were ignored
  without notice; include = {} selects all atoms (of the cells set by
  cells).

  The default output directory name CluE-<hash> is a hash of the parsed
  configuration, so it changes for the same input, since unused fields
  were removed from it.

REMOVED:
  The key output.run_name. Output directories are now named 
  automatically (see the new layout under CHANGED). output.run_name, and
  run_name at the top level of the old layout, are reported as removed.
  The test assets no longer set it.

  math::str_hash(), replaced by math::fnv1a_64().

  cosubstitute = "bonded", which did not group particles as intended, is 
  now an error that names the group. The options are "same_molecule", 
  "group" (or "filter"), and "particle". Tensor axes can still use 
  from_bonded_to and to_bonded_to.

  SecondaryParticleFilter::from(), which only parsed cosubstitute, and the
  error CluEError::CannotParseSecondaryParticleFilter, which only it used.

  space_3d::minimize_absolute_difference_for_vector3d_step(), which moved 
  vectors in the wrong direction and is no longer used.

  Config::max_spin_multiplicity_for_particle_config(), which looked up the
  same index in the primary cell and extracell group lists, so it mixed
  unrelated groups when cell_type was used, and is no longer used. Use
  ParticleConfig::max_possible_spin_multiplicity() on the group list of
  the particle's unit cell instead.

  The group selections isotopes and not_isotopes, which are now invalid
  keys. Groups are selected before isotopes are drawn, so these selections
  only saw the most common isotope of each element: isotopes = ["2H"]
  selected nothing, and isotopes = ["1H"] selected every hydrogen,
  including those later drawn as 2H. Use elements to select by element,
  and isotope-keyed group keys such as 2H.active or 2H.electric_quadrupole
  for settings of one isotope. Also removed: the fields
  ParticleFilter::isotopes and ParticleFilter::not_isotopes, and the
  constants KEY_SELE_ISOTOPES and KEY_SELE_NOT_ISOTOPES.

  Error variants that were never returned: FilterNeedsALabel,
  SpinPropertiesNeedsALabel, SpinPropertiesNeedsAnIsotope,
  StructurePropertiesNeedsALabel, StructurePropertiesDoesNotNeedAnIsotope
  and NoUnitOfClustering (used only in commented-out code, the first five
  for the .clue format removed in 0.2.3-alpha.1), and ExpectedTOMLBool,
  ExpectedTOMLString, ExpectedTOMLTable, IncorrectNumberOfAxes,
  InvalidDensityMatrix, InvalidPulse, NoClustersOfSize,
  TooManyExchangeCouplingsSpecified, TOMLValueDoesNotSpecifyAPartitionTable
  and ErrorPulseSequence (replaced by more specific variants). Also
  removed: CluEError::Generic, and the commented-out .clue token parser
  Config::parse_token_stream.

  Input keys that the code did not use: min_cell_size, max_cell_size,
  detected_spin.electric_quadrupole (the isotope key electric_quadrupole
  of [[groups]] is unchanged), pair_cutoffs.coupling (the cutoff is
  coupling_xx_yy), output.cluster_signals (cluster signals are written
  with output.auxiliary_signals), output.config, and the table [[pulses]]
  (the pulses are always built from detected_spin.transition). They are
  now rejected with the reason. Also removed: the Config fields
  min_cell_size, max_cell_size, write_cluster_signals, write_config, and
  detected_spin_quadrupole_coupling, and the constants KEY_OUT_CLU_SIGS
  and KEY_OUT_CONFIG.

  Selection by unit-cell index: selection.cell_ids and
  selection.not_cell_ids. The group key cells still distinguishes the
  primary cell from its periodic copies. Also removed: the fields
  ParticleFilter::cell_ids and ParticleFilter::not_cell_ids, the error
  CluEError::FilterAlreadySet, which only they used, and the constants
  of the old selection keys (KEY_SELECTION, KEY_CELL_TYPE,
  KEY_SELE_PRIMARY_CELL, KEY_SELE_NOT_*, KEY_SELE_BONDED_*, ...).
  ParticleFilter::from_toml_table() and set_from_toml_table() are replaced
  by from_toml_tables() and set_from_toml_tables(), which read the
  include and exclude tables of a group.

CluE Oxide: 0.2.2-alpha.3

ADDED: 

Partitioning CCE (pCCE)[1,2] has been added.  
Note that keyword related to pCCE are liekly 
to change in the next couple versions.
The keword "partitioning_method" can be used to select the partitioning method.
Currently the available methods are "particles", which is the same as normal
CCE, and "exchange_groups_and_particles" which partitions methyls and
primary amonium groups as a block and all other spins as their own blocks.
The "unit_of_clustering" can be "spin" or "set".  This determines what the n
in n-CCE referes to.  For example, a block that contains a methyl group,
is one block, but contains three spins, so 
  unit_of_clustering = set;
treats the methyl as a 1-cluster, while 
  unit_of_clustering = spin;
treats the methyl as a 3-cluster.  Using the latter together with choosing the
"partitioning_method" makes "remove_partial_methyls" redundant.

Added keyword "max_spin_order".  This will drop clusters with more than the 
specified number of spins.  For example when "unit_of_clustering" is "set",
a 2-cluster of of a hydrogen and a methyl group contains four spins,
but a 2-cluster of two methyl groups contains six spins.  
Setting "max_spin_order = 4;", will keep the former cluster, 
but drop the latter.
Note that "max_spin_order" should not be used if "unit_of_clustering" is "spin".

REMOVED:

The "remove_partial_methyls" keyword has been removed.  
See above on the addition of pCCE.

CHANGED:

Fixed bug where a leading "+" in the exponent in e-notation such as "1e+11",
would get parsed incorrectly.

The input modes "#[group()]", "#[structure_properties()]", and
"#[spin_properties()]" can now take either positional arguments or keyword
arguments.

Groups can be made specific to the primary unit cell by adding
  primary_cell;
within a #[group()] section, or to all cells other than the primary cell via
  extracells;

  cosubstitute = same_molecule;
is now available to enforce that atoms in the group my_label that are on the
same molecule are the same isotope.  Note that atoms not in the my_label group
are not affected regardless of which molecule they are on.
